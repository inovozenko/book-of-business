## 1. Контекст

Что строим: одну страницу Clients с двумя частями.

- Stacked bar chart: клиенты по месяцам с разбивкой по каналам привлечения.
- Таблица по месяцам с раскрываемыми строками: Company → Branch → Adviser → Channel.

Требования брифа, которые определяют решения:

- React и TypeScript; данные отдаёт Node.js REST API; в UI есть состояния загрузки и ошибки.
- API компонентов как в реальной команде: composable, с понятными границами.
- Доступность: раскрытие и сворачивание работает с клавиатуры, иерархия доходит до assistive technology.
- Тесты минимум на раскрытие и сворачивание и на то, как данные ложатся в чарт.
- Ничего не ломается и не вылезает за экран до ширины 375px.
- README: запуск и тесты, допущения, открытые вопросы, что дальше.

Вложенность неравномерная: у Branch 2 и Branch 3 нет сотрудников, каналы есть только у Anna Blackwood.

## 2. Решения

### 2.1 Frontend

- React 19, TypeScript в strict mode, Vite.
- **React Aria Components напрямую, без shadcn/ui и без Tailwind.** Стили — SCSS с CSS Modules (`*.module.scss`),
  с семантическими именами классов и токенами в CSS-переменных.
  Почему: shadcn для таблицы даёт только файл-обёртку с Tailwind-классами, всё поведение приходит из React Aria.
  С shadcn получались две системы стилей на одну страницу и скопированный код, который обновляется вручную.
  Без него остаётся одна зависимость, обновляемая через npm, и одна система стилей.
- Минимум кода и зависимостей, чтобы страница была быстрой. В рантайме клиента только `react`, `react-dom`,
  `react-aria-components` и `recharts`, плюс файл шрифта; CSS-фреймворка нет. Сборка делится на чанки
  React, React Aria и остальных библиотек (около 220, 195 и 300 kB), код приложения — 13 kB: так библиотеки
  кешируются отдельно и грузятся параллельно.
- Шрифт макета — Inter 4: Inter и Inter Display — это одна переменная гарнитура с осью optical size.
  Подключаем пакетом `@fontsource-variable/inter` через свой `@font-face` на один латинский файл с осями
  `wght` и `opsz`: файл лежит в сборке, `font-display: swap`, без запросов к чужим серверам. При
  `font-optical-sizing: auto` браузер сам берёт Inter Display на 35px и текстовый Inter на 12–14px.
- React Aria работает в локали `en-US` (`I18nProvider`): иначе подписи Expand и Collapse идут на языке
  браузера, а страница на английском.
- Состояние: только локальный React state. Без Redux, Zustand, MobX и TanStack Query — на странице один GET.
- ESLint и проверяет код, и форматирует его: ESLint Stylistic вместо Prettier.
  Почему: Prettier не настраивается под нужный стиль. Нужны пустые строки вокруг блоков и групп объявлений, `from`
  в колонку, импорты группами (фреймворки, библиотеки, код приложения), атрибуты в порядке Code Guide
  (codeguide.co) и строка до 240 символов. Чего нет в ESLint Stylistic, делают три своих правила в
  `eslint-rules/`. Стиль применяет `npm run format`.
- Семантическая вёрстка: `main`, `h1`, `figure` для чарта, нативная `table`.

### 2.2 Таблица

`Table` из `react-aria-components` с раскрываемыми строками (`treeColumn`, `expandedKeys`,
`<Button slot="chevron">`). Разметку и ARIA не пишем сами; из клавиатуры своё только Tab по строкам (T9).

Проверено на версии 1.21.1 на нашей иерархии:

- Разметка: нативная `<table role="treegrid">`, строки `<tr>` с `aria-level`, `aria-posinset`, `aria-setsize`.
- `aria-expanded` есть только у строк с детьми.
- Клавиатура: стрелки вверх и вниз переходят по строкам, вправо раскрывает, влево сворачивает, Enter
  переключает. Сама библиотека делает таблицу одной остановкой Tab, как велит паттерн treegrid.
- Клик ставит фокус на ячейку, а не на строку; стрелка влево с первой ячейки возвращает фокус на строку.
- Кнопка-стрелка сама получает подпись Expand или Collapse. Эта подпись входит и в имя ячейки-заголовка
  строки («Collapse Company») — так устроена библиотека, оставляем.
- Для стилей доступны `--table-row-level`, `[data-level]`, `[data-has-child-items]`, `[data-expanded]`.
  `[data-hovered]` библиотека ставит только строкам с действием.

Что библиотека не даёт и что пишем сами (`components/ui/TreeTable`):

- Анимация раскрытия и сворачивания (T7): библиотека монтирует строки и сразу размонтирует их.
- Tab по строкам (T9).
- Ключи колонок с префиксом: колонки и строки у React Aria в одном пространстве ключей, и узел с id `"1"`
  совпадал с колонкой месяца — таблица падала.
- React Aria кеширует отрисованные строки. Всё, что строка читает кроме своего элемента (раскрытые ключи,
  колонки, функции рендера), передаётся в `dependencies`, иначе обработчики видят устаревшие ключи: клик
  по Anna сворачивал Branch 1.
- Доменная обёртка (`features/clients/ClientsTable`): колонки месяцев, аватар у узлов из `employees`, числа
  с разделителями разрядов, полное имя в `title`, когда оно обрезано многоточием.
- Скрытое имя первой колонки (`Name`) для скринридера: в макете ячейка пустая.
- Без строк и с `emptyState` таблица показывает заголовок и под ним пустое состояние. Без строк в таблице нечего
  читать и некуда ходить, поэтому клавиатура и скринридер идут к пустому состоянию: сама `<table>` — `inert`,
  прокручиваемый контейнер — `aria-hidden` и `tabIndex={-1}` (браузеры делают контейнер прокрутки без фокусируемого
  содержимого отдельной остановкой Tab). `inert` стоит на таблице, а не на контейнере: так заголовок шире экрана
  прокручивается колесом, пальцем и полосой прокрутки, как таблица с данными.
  `renderEmptyState` из React Aria не подходит: он кладёт содержимое строкой внутрь грида, а React Aria считает
  грид одной остановкой Tab и при нажатии Tab перепрыгивает всё, что внутри, в том числе кнопку Retry.
  Нижние углы прокручиваемого контейнера тогда без скругления, иначе они срезают линию под заголовком.
- Управление фокусом. Фокус стоит на строках и никогда не теряется:
  - клик ставит фокус на свою строку, а не на ячейку под курсором, поэтому стрелки идут дальше от строки,
    а влево и вправо сворачивают и раскрывают её. React Aria ставит фокус на ячейку при нажатии и ещё раз после
    раскрытия, поэтому перенос делается на следующем кадре;
  - вход в таблицу по Tab начинается с первой строки, по Shift+Tab — с последней, а не с той, где фокус был
    в прошлый раз;
  - строки, которые уезжают при сворачивании, отключены (`isDisabled`): стрелки и Tab их пропускают;
  - если фокус внутри ветки, которая сворачивается, он переходит на свёрнутую строку;
  - любой отложенный перенос фокуса отменяется, если пользователь успел нажать клавишу или ушёл из таблицы.
  Без этого фокус после сворачивания падал на `body`, и стрелки начинали прокручивать страницу вместо таблицы.
- Видимый фокус у строки, ячейки и заголовка колонки: в макете его нет, вид свой — кольцо 2px `#5b3fd6`.
  Кольцо ячейки и заголовка колонки рисуется поверх неё, а не тенью: тень перебивало правило, которое убирает
  разделитель у последней строки, и фокус на ячейках последней строки был не виден. Кольцо последней колонки
  захватывает правое поле таблицы, как кольцо первой — левое, и доходит до края; в четырёх углах карточки
  кольца скруглены вместе с ней.
  Каждая ячейка рисует свою часть кольца с заходом на пиксель в соседнюю: на дробной ширине колонок части,
  которые только касались, давали белые швы. У последней строки нижние углы скругляются по карточке
  (переменная `--tree-table-radius`), чтобы кольцо и hover не обрезались.

Поведение:

- По умолчанию раскрыт корень (Company), как в макете.
- Клик по строке с детьми раскрывает и сворачивает её, как в прототипе: `onAction` у `Row`, только для строк
  с детьми.
- Строки без детей: без стрелки (T1), но с hover, как все строки (T2).

Рассмотренные альтернативы:

| Вариант | Почему нет |
|---|---|
| shadcn/ui на базе React Aria | Только оформление поверх той же библиотеки; тянет Tailwind |
| Base UI, Radix | Нет компонентов таблицы |
| TanStack Table | Headless: разметку, ARIA и клавиатуру пришлось бы писать самим |
| AG Grid, MUI X Data Grid | Древовидные данные только в платных редакциях; тяжёлые, свой внешний вид |
| Своя `<table role="treegrid">` | Был запасным вариантом; проба прошла (8.1), не понадобился |

React Aria — открытая библиотека Adobe под Apache 2.0, без платной версии и привязки к продуктам Adobe.

### 2.3 Чарт

- Recharts версии 3.6 или новее. `BarStack` скругляет стек целиком, поэтому пустая верхняя категория
  не ломает скругление.
- Чарт всегда показывает корень дерева и не реагирует на раскрытие строк, как в прототипе.
- Маппинг данных — чистая функция в `lib/chart-data.ts`, тестируем её, а не SVG (см. T4):
  - правило общее и не зависит от формы дерева: каналы могут лежать на любом уровне вложенности;
  - канал — это узел с `kind: 'channel'` (см. 2.4); другого признака нет;
  - каналы собираются рекурсивно и группируются по имени. Если у узла есть свои каналы, берём их
    и глубже по этому узлу не спускаемся; иначе складываем каналы его детей. Так одни и те же клиенты
    не считаются дважды, когда разбивка дана на двух уровнях одной ветки;
  - для чарта канал — лист: берём его `values`, его собственных детей не обходим. В таблице такие дети
    показываются обычными строками;
  - `Existing clients` — значение корня минус сумма остальных каналов. Собственные значения канала
    `Existing clients` из данных в расчёте не участвуют;
  - высота столбца равна значению корня; на данных задания серий три, как в легенде макета;
  - канал с новым именем становится отдельной серией;
  - какой канал получает остаток, задаёт доменный слой (`features/clients/channels.ts`): имя приходит
    в функцию параметром. Сама функция в `lib/` об именах каналов не знает;
  - категория с нулём не рисуется; серия, где все значения нулевые, не попадает в легенду;
  - если сумма остальных каналов больше значения корня, `Existing clients` равен нулю;
  - если каналов в дереве нет, весь столбец — `Existing clients`.
- Порядок в стеке снизу вверх: `Existing clients`, `New organic`, `New paid`, как в макете; легенда
  в том же порядке. Серия с остатком всегда внизу, остальные идут в порядке появления в данных.
- Цвета трёх серий берутся из макета и привязаны к именам каналов в доменном слое. Для каналов
  с новыми именами в токенах есть запасная палитра из четырёх цветов.
- Ось Y: пять линий сетки, то есть четыре интервала. Шаг — наименьшее из чисел вида 1, 2, 5 × 10ⁿ
  (не меньше 1), при котором четыре шага покрывают самый высокий столбец; верхняя граница равна четырём шагам.
  На данных задания шаг 100 и ось 0–400; при максимуме 38 ось 0–40; при нулевых данных 0–4.
  Расчёт — чистая функция в `lib/axis.ts` (там же сумма стека по категориям), под тем же порогом покрытия:
  в компоненте его не проверить, потому что Recharts в jsdom не рисуется.
- Ширина столбца — `barSize` в процентах от оси: вычисленную ширину Recharts округляет (87,5 → 88px),
  а процентную нет. На 1440px столбец ровно 87,5px, на узком экране сужается в той же пропорции.
- Подписи осей рисуют свои функции тиков с атрибутом `data-axis`: так их положение совпадает с макетом
  с точностью до пикселя, а E2E находит их без внутренних классов Recharts.
- Ширина оси Y — `width="auto"` у Recharts: он меряет элементы с классом тика. Подпись лежит в группе с пустым
  прямоугольником шириной 26px, колонкой подписей из макета, поэтому короткие подписи дают ровно 38px с зазором,
  как в макете, а длинные, от четырёх знаков, раздвигают ось вместо того, чтобы обрезаться. SVG чарта не обрезает
  содержимое: подпись, измеренная до загрузки Inter, может зайти на поле карточки.
- Год без клиентов: столбцов нет, ось всё равно 0–4. Без данных Recharts берёт заданный домен оси только
  с `allowDataOverflow`, иначе ось не рисуется. Наш домен всегда выше самого высокого столбца, так что на обычных
  данных флаг ничего не меняет. Посреди области графика стоит подпись из пропса `emptyMessage` («No clients
  in this period»), фон карточки прерывает под ней линию сетки. Легенды нет, но её строка остаётся пустой:
  высота чарта та же, что с данными и у скелетона.
- Tooltip не делаем: в макете его нет.
- Доступность: у SVG чарта `role="img"` и `aria-label` через пропсы Recharts; `title` не подходит — браузер
  показал бы его подсказкой. Легенда — обычный список с именем Legend, а не `figcaption`: иначе она становится
  именем всего `figure`. Полные данные — в таблице ниже. `accessibilityLayer` у Recharts выключаем: в версии 3
  он включён по умолчанию, ставит чарт в порядок Tab и ждёт Tooltip, которого у нас нет.

### 2.4 Модель данных

- API отдаёт payload из задания без изменений: ключи `branches`, `employees`, `channels` остаются.
- Форму дерева предсказать нельзя, поэтому она нигде не зашита. Узел может содержать любой из ключей
  `branches`, `employees`, `channels` на любом уровне, в том числе несколько сразу или ни одного.
- Клиент на границе (`lib/hierarchy.ts`) приводит ответ к рекурсивному узлу
  `{ id, name, kind, values, children }`. `kind` — одно из `company`, `branch`, `employee`, `channel`
  и выводится из ключа, под которым лежал узел; у корня ключа нет, его `kind` всегда `company`.
  Дети идут в порядке ключей: `branches`, `employees`, `channels`.
- Проверка ответа только структурная. Правила одни для узла на любой глубине:
  - узел — объект; `id` — непустая строка; `name` — строка;
  - `values` — массив ровно из 12 конечных неотрицательных чисел. Дробные значения допустимы
    и показываются как есть, с дробной частью. Числа в таблице и на оси выводятся с разделителями разрядов
    в локали приложения (`APP_LOCALE`, `en-US`): 153,953;
  - ключ `branches`, `employees` или `channels` либо отсутствует, либо содержит массив объектов.
    Пустой массив равен отсутствию ключа. Любое другое значение, включая `null`, — нарушение;
  - `id` уникален в пределах дерева: он служит ключом строки в таблице. Любой непустой id допустим,
    в том числе `"1"`: с ключами колонок он не пересекается (2.2);
  - остальные ключи узла игнорируются.
- Ответ без тела, `null` и `[]` — не нарушение, а отсутствие данных (`isEmptyPayload`, см. 2.6). `{}` и массив
  компаний — нарушения: корень ответа — одна компания.
- Одно нарушение на любой глубине делает невалидным весь ответ: показываем состояние ошибки, частично
  дерево не рисуем. Ошибка содержит путь к месту нарушения. Суммы не проверяем и не исправляем (см. T6).
- Проверка, нормализация и подготовка данных для таблицы и чарта — чистые функции в `lib/`.
  `api/clients.ts` только делает запрос. Эта логика покрыта тестами на 100% (см. 2.8).
- Типы контракта общие для клиента и сервера: `shared/clients.ts`.

### 2.5 API

- Hono, TypeScript, REST. Одно приложение, две точки входа:
  - `server/src/node.ts` — Node.js через `@hono/node-server`. Это основной способ запуска и ответ
    на требование брифа про Node.js REST API.
  - `server/src/worker.ts` — Cloudflare Worker для публичного демо (см. T8). Это одна строка,
    `export default app`: типы Workers не нужны.
- `server/src/app.ts` содержит только маршруты API. Статику клиента на Node добавляет `node.ts`
  (`serveStatic` из `@hono/node-server/serve-static`, папка `dist/client`), на Workers её отдаёт платформа.
- Без параметров работает набор данных из задания: страница `/` и запрос `GET /api/clients`
  отдают payload из брифа. Тест сверяет `server/src/data/assignment.json` с JSON из брифа.
- `GET /api/clients?year=2024` возвращает payload за отчётный год (см. T3). Год по умолчанию, 2024, —
  константа в `shared/`, общая для клиента и сервера. Неизвестный год — 404.
  Все наборы данных, включая фикстуры, относятся к 2024 году: другой год даёт 404 при любом `dataset`.
  Годом считается только строка `2024`; `year=abc`, пустое значение и любой другой год — тоже 404,
  отдельного 400 нет.
- Наборы данных переключаются ключом `dataset` в URL: страница `/?dataset=<имя>` передаёт
  его в запрос `GET /api/clients?dataset=<имя>`. Неизвестное имя даёт 404.
- Набор из задания называется `assignment` и стоит в списке первым; запрос без `dataset` равен
  `dataset=assignment`.
- Ответ 404 — JSON `{ "error": "Unknown dataset" }`, `{ "error": "Unknown year" }` или
  `{ "error": "Unknown scenario" }`; сначала проверяется `dataset`, потом `year`, потом `scenario`. Список этих
  ошибок — `NOT_FOUND_ERRORS` в `shared/`. Клиент текст из ответа не показывает, но по нему отличает «нет данных»
  от сбоя (2.6).
- Демо-сценарии для состояний страницы — ключ `scenario`, страница передаёт его в запрос как есть, как `dataset`
  и `year`. `slow` держит ответ 2 секунды и отдаёт набор (видна загрузка); `error` тоже ждёт 2 секунды и отвечает
  500 `{ "error": "Server error" }`, так что скелетон виден перед ошибкой и после Retry; `empty-response` сразу
  отвечает `[]` (нет данных). Без `scenario` ответ без задержки. Набор и год при этом проверяются и действуют.
  Retry при `error` снова получает 500: сценарий — часть адреса.
- Клиент читает `year` и `dataset` из адреса один раз при загрузке (`features/clients/clients-query.ts`)
  и передаёт в запрос как есть, сам их не проверяет. Подписи месяцев строит по адресу, не дожидаясь ответа
  (`reportingMonths`): они нужны и без данных (2.6). Год по умолчанию — 2024; текст, который не год из четырёх
  цифр, даёт 12 пустых подписей, колонки остаются на местах.
- Наборы данных лежат в `server/src/data/` в JSON, по файлу на набор, в структуре брифа: компания держит `branches`,
  филиал — `employees`, сотрудник — `channels`, и на любом уровне данные либо есть в такой форме, либо отсутствуют.
  Каналы под филиалом или компанией, как в прежнем наборе `channels-mixed-levels`, в наборы не входят; функция чарта
  такие случаи по-прежнему умеет, их покрывают unit-тесты. Existing clients в наборах накопительные: база месяца —
  база прошлого месяца плюс его новые клиенты минус отток; нули посреди года есть только в `empty-categories`,
  где все клиенты ушли. Наборы: `assignment` (бриф, `assignment.json` совпадает с JSON из брифа байт в байт),
  `empty`, `full`, `no-employees`, `no-channels`, `partial-channels`, `empty-categories`, `single-level`,
  `long-names`, `large-numbers`, `inconsistent-totals`; что показывает каждый — в таблице README. Список наборов
  в `index.ts` — один массив: по нему работает и API, и E2E (см. 2.8). Источник — сами JSON-файлы; ожидания
  для E2E посчитаны по ним отдельно от кода приложения и записаны константами в `expectations.ts`.

### 2.6 Состояния загрузки, «нет данных» и ошибки

В макете их нет, вид свой, в стиле карточек макета.

- Загрузка: skeleton на месте чарта и таблицы, контейнер с `aria-busy`. Сообщение «Loading clients…» стоит
  в постоянной live-области (`role="status"`), поэтому скринридер объявляет его после Retry: область, которая
  появляется сразу с текстом, часто не объявляется.
- Скелетон не мигает. Он появляется, только если ответа нет 200 мс, и держится не меньше 400 мс, даже если ответ
  пришёл раньше: ответ ждёт. Одной задержки мало: ответ на 210-й миллисекунде мигнул бы скелетоном на 10 мс. Цена —
  до 400 мс ожидания в худшем случае. До 200 мс под заголовком пусто при первой загрузке, а при Retry остаётся
  прежняя ошибка. `aria-busy` и «Loading clients…» появляются вместе со скелетоном, поэтому быстрый ответ скринридер
  не объявляет. Тайминги — хук `useLoadingIndicator` в `hooks/`.
- «Нет данных» и ошибка рисуют страницу без данных на месте скелетона, поэтому при переходе ничего не прыгает:
  карточки те же по месту и размеру, что у скелетона и у страницы с данными. Чарт — с осью 0–4, месяцами и короткой
  подписью в центре; он скрыт от скринридера, потому что это картинка пустоты. Таблица — с заголовком месяцев,
  под ним сообщение: его и читает скринридер, при ошибке там же Retry. Заголовок таблицы без строк скрыт
  от скринридера и клавиатуры, но прокручивается (`emptyState` у `TreeTable`, 2.2). Если такая страница сама
  не отрисуется, сообщение показывается отдельно.
- Нет данных: API ответил, что для запроса у него ничего нет, и повтор даст тот же ответ. Это 404, в теле
  которого `error` из `NOT_FOUND_ERRORS` (неизвестный набор, год или сценарий), а также ответ без тела (204),
  `null` и `[]`. На чарте и под заголовком таблицы «No client data», без Retry; та же фраза — в live-области,
  она там с начала загрузки и объявляется надёжно. В консоль не пишется: это не сбой.
- Ошибка: всё остальное — 5xx, сетевая ошибка, тело не JSON, ответ не проходит проверку структуры (в том числе
  `{}`), 404 без такого `error`, например от несуществующего маршрута. На чарте «Clients could not be loaded»,
  под заголовком таблицы сообщение с `role="alert"` и кнопка Retry. Пока идёт повтор, ошибка и кнопка остаются
  на экране, фокус — на кнопке, повторное нажатие ничего не делает. Быстрый ответ с той же ошибкой оставляет всё
  как было. Когда кнопку сменяет скелетон или ответ, фокус переходит на заголовок страницы, а не теряется.
  `isPending` у кнопки React Aria не подходит: он зачитывает её имя при каждом нажатии и ещё раз в конце.
  Неудачная загрузка пишется в консоль.
- Год без клиентов — не «нет данных»: компания пришла, её нули — данные. Таблица показывает нули, чарт — ось 0–4
  и подпись (2.3).
- Ошибка рендера чарта или таблицы ловится `ErrorBoundary` и даёт то же состояние ошибки, а не пустую страницу.
- Логика в `use-clients.ts`: последний ответ, признак идущего запроса, отмена запроса при размонтировании,
  повтор. Признак «нет данных» у ответа
  с ошибкой — `ClientsRequestError.noData` в `api/clients.ts`, у успешного — `isEmptyPayload` в `lib/hierarchy.ts`.

### 2.7 Вёрстка и адаптивность

- Цель — pixel-perfect по макету на ширине 1440px и для чарта, и для таблицы. Размеры, отступы, цвета,
  шрифты и радиусы взяты из Figma и заведены токенами в `styles/tokens.scss`.
- Проверка: снимок страницы на ширине контента 1440px сравнивается со снимком Mockup 2 из прототипа. Позиции
  текста и линий совпадают в пределах 1px; остаток разницы — сглаживание шрифта у браузера и Figma и высоты
  столбцов, которые в макете нарисованы вручную (см. T4). Автоматического pixel-diff в тестах нет.
- Высота строки заголовка — 44px, как блок в Figma: при 1,25 × 35 = 43,75px всё ниже сдвигалось на четверть
  пикселя, и линии таблицы размывались.
- Колонка имени фиксирована, колонки месяцев делят остаток поровну, как `flex: 1` в макете, но не уже 68px
  (влезает «May 2024»); на 1408px каждая ровно 92px. Правое поле 24px — отдельная пустая ячейка в конце каждой
  строки, чтобы последняя колонка месяца была как остальные. С жёсткими колонками при классической полосе
  прокрутки (окно 1440px, контент 1425px) таблица уезжала в горизонтальный скролл.
- Под полосу прокрутки зарезервировано место (`scrollbar-gutter: stable`): иначе в момент её появления страница
  сужается на 15px и чарт перерисовывается со сдвигом. На системах с накладными полосами ничего не меняется.
- До 375px страница не скроллится по горизонтали.
- Таблица скроллится внутри своей карточки. Первая колонка закреплена на ширине от 768px; на более
  узких экранах закрепление отключено, иначе колонка в 264px оставит место для одного месяца.
- Чарт помещается в ширину; при нехватке места подписи оси X прореживаются с ровным шагом от первого месяца
  (`interval="equidistantPreserveStart"`): Feb видна всегда, дальше каждая вторая, третья или четвёртая подпись.
  Recharts берёт наименьший шаг, при котором все подписи влезают. Вариант `preserveStartEnd` держал и первую,
  и последнюю подпись, но заполнял середину жадно, и ритм ломался: на 1000px шаги были 2, 1 и 3. Ширину подписей
  Recharts меряет шрифтом, который находит по классу `recharts-cartesian-axis-tick-value`; без этого класса у наших
  подписей он мерил шрифтом страницы, 14px вместо 12px, и прятал подписи раньше нужного.
- Анимации отключаются при `prefers-reduced-motion`.

### 2.8 Тесты

- Vitest, unit. Преобразование ответа API в данные для таблицы и чарта (`client/src/lib/**`) покрыто на 100%:
  строки, ветви и функции. Порог задан в конфиге Vitest для этой папки, `npm test` и CI падают, если он не выполнен.
  Процент не заменяет сценарии, обязательный список:
  - нормализация: payload из задания; узел без детей; пустые массивы; каналы прямо под компанией;
    каналы под филиалом; узел с двумя ключами сразу; глубокая вложенность; неизвестные ключи игнорируются;
  - проверка структуры: нет `id` или `name`; пустой `id`; `values` не массив, не 12 элементов, не числа,
    отрицательное число; ответ не объект; `branches` не массив или равен `null`; элемент массива детей
    не объект; повтор `id` в разных ветках; нарушение на третьем уровне вложенности;
  - ось: максимум 350 даёт 0–400; 38 даёт 0–40; ровно 400 даёт 0–400; 401 даёт 0–800; ноль даёт 0–4;
  - чарт: payload из задания даёт числа из T4; дерево без каналов; каналы на разных уровнях в разных ветках;
    каналы на двух уровнях одной ветки не считаются дважды; одноимённые каналы у разных узлов складываются;
    канал с новым именем; сумма каналов больше корня; серия из одних нулей; нулевая категория в месяце;
    дети канала в расчёт не попадают;
  - период: 12 подписей от февраля заданного года с переходом на январь следующего.
- Маршрут API: каждый набор данных, неизвестные `dataset`, `year` и `scenario`, порядок проверок, сценарии
  `slow` (на поддельных таймерах), `error` и `empty-response`; payload из задания совпадает с брифом.
- React Testing Library и user-event: раскрытие и сворачивание кликом, кнопкой, стрелками и Enter, `aria-expanded`,
  `aria-level` и `aria-posinset`, отсутствие стрелки у строк без детей, id строк вида `"1"`, Tab по строкам,
  анимация (отметка появляющихся строк, сворачивание после анимации, повторное раскрытие во время сворачивания),
  состояния загрузки, «нет данных» и ошибки на каждом виде ответа из 2.6, Retry и фокус после него (быстрый
  и медленный повтор), отсутствие скелетона у быстрого ответа, `ErrorBoundary`. Тайминги скелетона — тесты
  `useLoadingIndicator` на поддельных таймерах: ответ за 50 мс, за 250 мс, за 2 с.
  В настройке jsdom нужны заглушки `scrollTo`, `scrollIntoView` и `ResizeObserver`: без них React Aria падает
  при переходе по строкам, а Recharts не знает размеров. Они лежат в `client/src/test/setup.ts`.
- Playwright работает в Chromium по собранному приложению: `webServer` запускает `npm run build && npm start`
  на порту 3101, то есть тот же Node-сервер, что и у проверяющего.
- Playwright: отдельный сценарий на каждый набор данных — payload из задания и каждую фикстуру.
  Тест перебирает общий список наборов, поэтому новый набор сразу получает свой сценарий. В каждом:
  открытие страницы с ключом `dataset`, раскрытие дерева до нижнего уровня с клавиатуры и сворачивание,
  проверка строк таблицы, серий и оси чарта, ожидаемых для этого набора, проверка axe на раскрытой таблице.
  Ожидания для каждого набора записаны вручную в `server/src/data/expectations.ts` рядом с фикстурами,
  а не вычисляются тем же кодом, который проверяется.
  Состояния страницы — в `e2e/states.spec.ts`: неизвестные `dataset`, `year` и `scenario` и ответы `[]`, `null`,
  204 дают «нет данных»; `{}`, тело не JSON, 500 и HTML-страница 404 дают ошибку с Retry; сценарии `slow`,
  `error` и `empty-response`; Retry после сбоя. В «нет данных» и ошибке у чарта ось 0–4 и подпись, у таблицы
  заголовок месяцев; карточки скелетона, ошибки, «нет данных» и данных на одних местах и одного размера; на 375px
  заголовок без данных прокручивается, а Tab от заголовка страницы попадает сразу на Retry; быстрый ответ
  не показывает скелетон; быстрый Retry с той же ошибкой оставляет фокус на кнопке, медленный переводит его
  на заголовок. Ответы подменяются через `page.route`, на каждом состоянии проверка axe. Отдельно: у года
  без клиентов чарт той же высоты, что с данными; на 375px нет
  горизонтального переполнения; hover у строк с детьми и без; анимация и её отключение
  при `prefers-reduced-motion`.
- Сценарии клавиатуры и фокуса — в `e2e/keyboard.spec.ts`, и они идут в Chromium, Firefox и WebKit: обработка
  фокуса у движков разная. Стрелки до последней строки, Home и End; клик ставит фокус на строку; фокус
  не теряется при сворачивании и следующем нажатии; Tab пропускает уезжающие строки; сворачивание кнопкой
  уводит фокус на свёрнутую строку; Tab по строкам и выход после последней; вход по Tab с первой строки;
  стрелка вправо в ячейки и вниз по ячейкам до последней строки. На каждом шаге проверяется, что кольцо
  фокуса видно там, куда ушёл фокус.

### 2.9 Доставка и хостинг

- Локально API работает только в Node.js runtime: `npm install`, `npm run dev` поднимает Vite и Node API,
  Vite проксирует `/api`. Эмулятор Workers для разработки не используем.
- Команды:

  | Команда | Что делает |
  |---|---|
  | `npm run dev` | `concurrently` запускает Vite на 5173 и `tsx watch server/src/node.ts` на 3001 |
  | `npm run build` | `tsc -b` и `vite build`, результат в `dist/client` |
  | `npm start` | `tsx server/src/node.ts`: один порт отдаёт `/api` и собранный клиент из `dist/client` |
  | `npm run typecheck` | `tsc -b` |
  | `npm run lint` | ESLint |
  | `npm run format` | `eslint . --fix`: применяет стиль кода |
  | `npm test` | Vitest с покрытием |
  | `npm run test:e2e` | Playwright |
  | `npm run deploy` | `wrangler deploy` |

- Порт API — 3001, переопределяется переменной `PORT`.
- Серверный TypeScript запускает `tsx`, отдельной сборки сервера нет.
- Демо на бесплатном тарифе Cloudflare: один Worker отдаёт и статику SPA, и `/api`. Один origin, CORS не нужен.
- `wrangler.jsonc`: `main` — `server/src/worker.ts`, `assets.directory` — `./dist/client`, `build.command` —
  `npm run build`, поэтому деплой и dry-run сами собирают клиент. SPA-fallback (`not_found_handling`)
  не включаем: маршрут у страницы один, `/`. Запрос, для которого нет файла, Cloudflare передаёт в Worker,
  поэтому `/api/*` доходит до Hono без `run_worker_first`.
- `wrangler deploy --dry-run` проходит, Worker весит 65 KiB. Один раз Worker проверен локально через
  `wrangler dev`: страница, API и 404 отвечают. В разработке он не используется, дальше его проверяет CI.
- Worker называется `book-of-business`, демо — https://book-of-business.inovozenko.workers.dev. Названия
  компании из задания в адресе нет. Первый деплой сделан вручную, дальше деплоит CI.
- GitHub Actions, один workflow `.github/workflows/ci.yml`:
  - запускается на push в `main`, на pull request и вручную;
  - `check`: lint, проверка типов, unit-тесты, `wrangler deploy --dry-run`. `e2e`: Playwright в трёх
    движках, при падении трейсы сохраняются в артефакт. Обе задачи идут параллельно;
  - `deploy`: только из `main` и только когда обе задачи прошли. `wrangler deploy` в окружении `production`,

    старую версию, поэтому проверка повторяется в течение минуты;
  - в PR новый push отменяет прошлый прогон, а в `main` прогоны доходят до конца, чтобы не оборвать деплой.
- Node.js 24 LTS локально и в CI (поддержка до апреля 2028). Версия записана в `.nvmrc`, CI читает её
  оттуда. В `package.json`: `engines.node` `>=24`; `@types/node` остаётся `^24` из шаблона, то есть типы
  совпадают с версией, на которой код запускается.
- С Node 24 приходит npm 11: он не выполняет install-скрипты зависимостей без разрешения и пишет
  предупреждение. `esbuild`, `tsx` и `wrangler` работают и без них (проверено на npm 11.19), поэтому
  скрипты не разрешаем. Если пакет без скрипта не работает, разрешаем его поимённо.
- Деплою нужны секреты репозитория `CLOUDFLARE_API_TOKEN` (токен по шаблону «Edit Cloudflare Workers»)
  и `CLOUDFLARE_ACCOUNT_ID`. Workflow готов и заработает, когда появится удалённый репозиторий (раздел 8).

## 3. Trade-offs: отклонения от макета и допущения

Этот раздел переносится в README как ответ на просьбу брифа рассказать, что мы предположили и почему
и что, по нашему мнению, в задании неверно.

### T1. Стрелка раскрытия у строк без детей

- В макете: стрелка есть у всех уровней, кроме Attribute, в том числе у Branch 2, Branch 3 и у всех advisers.
  В прототипе клик по такой стрелке ничего не делает.
- Решение: если у элемента нет children, стрелку не показываем. Отступ сохраняем, чтобы имена
  соседних строк стояли на одной линии.
- Почему: элемент управления, который ничего не делает, вводит в заблуждение и мышь, и клавиатуру,
  и скринридер. По правилам treegrid у листа не должно быть `aria-expanded`.
- Цена: расхождение с макетом на уровне компонента `Row name`.

### T2. Hover у всех строк

- В макете: фон при наведении есть у любой строки, включая каналы (`Row`, свойство `On hover`).
- Решение: так и делаем — hover у всех строк, с детьми и без. Курсор-указатель только у строк, которые
  раскрываются. React Aria отмечает наведение только у строк с действием, поэтому подсветка — на CSS `:hover`
  и только на устройствах с мышью.
- Почему: в широкой таблице подсветка ведёт взгляд вдоль строки через двенадцать месяцев; для чтения это
  важнее. Третья редакция убирала hover у листьев, потому что подсветка обещает действие по клику; автор
  после просмотра вернул его.
- Цена: подсветка есть и у строк, клик по которым ничего не делает; на это указывает только курсор.

### T3. Год в URL

- В задании: в payload нет дат, подписи Feb 2024 – Jan 2025 есть только в макете.
- Решение: отчётный год — часть URL и точка входа. Страница `/?year=2024` запрашивает
  `GET /api/clients?year=2024`. Клиент строит 12 подписей от февраля указанного года.
  Без параметра работает набор данных из задания: год по умолчанию 2024. Адреса `/` и `/?year=2024`
  равнозначны, редиректа между ними нет, адрес страница не переписывает.
  Неизвестный год даёт 404 и состояние «нет данных» в UI (2.6).
- Почему: период становится явным и адресуемым, ссылкой на год можно поделиться.
  Payload из задания отдаётся без изменений.
- Цена: правило «год начинается с февраля» зашито константой в `shared/`. Правильнее, чтобы API
  возвращал период вместе с данными; это вопрос к авторам задания.

### T4. Что показывает чарт

- В макете: столбцы разбиты по каналам в масштабе всей компании. В payload каналы есть только
  у одного сотрудника, поэтому такую разбивку из данных получить нельзя.
- Решение: значения верхнего уровня (Company) уже есть, от них и считаем. `New organic` и `New paid` берём
  из тех каналов, что есть в данных, и вычитаем из значения Company; разность показываем как `Existing clients`.
  На данных задания `Existing clients` по месяцам: 250, 266, 282, 299, 315, 331, 348, 247, 248, 248, 248, 346.
- Почему: высота столбца сходится со строкой Company в таблице, серий три и легенда совпадает с макетом.
  Вариант «только известные каналы» дал бы столбцы высотой 25–38 под заголовком Clients при 250–350 в таблице.
  Вариант с отдельным нейтральным сегментом для клиентов без канала отклонён: в легенде появилась бы
  четвёртая серия, которой нет в макете, и она заняла бы большую часть столбца.
- Цена: `Existing clients` в чарте — расчётное число, а не данные API. В него попадают все клиенты,
  у которых канал неизвестен, поэтому оно не равно сумме строк `Existing clients` в таблице.
  Сегменты новых клиентов на этих данных равны 0–2 клиентам, то есть почти не видны.
- Область действия: это общее правило, а не решение под один набор данных. Каналы могут прийти
  на любом уровне вложенности, расчёт от этого не меняется (см. 2.3).

### T5. Аватары

- В макете: у строк уровня Adviser круглая фотография рядом с именем. В payload поля для неё нет.
- Решение: делаем по макету, с теми же пятью фотографиями. Они выгружены из Figma через MCP
  (вариант `0:1498` компонента Table · First and second levels), уменьшены до 60px — тройной плотности
  для аватара в 20px, около 7 kB каждая — и лежат в `client/src/assets/avatars/`. Соответствие
  «id сотрудника → файл» хранится в `features/clients/avatars.ts`. У изображения пустой `alt`, потому что
  имя стоит рядом. Если для сотрудника фотографии нет, `Avatar` показывает инициалы; они рисуются через
  CSS, чтобы не попадать в текст строки.
- Почему: строка совпадает с макетом, у каждого сотрудника своё лицо, а компонент `Avatar` уже принимает
  `src` и готов к настоящим данным.
- Цена: соответствие сотрудников и фотографий зашито в клиент и работает только для пяти людей из задания.
  Правильнее, чтобы ссылку на аватар отдавал API; это вопрос к авторам задания.

### T6. Несогласованные данные

- В задании: родительские значения местами не равны сумме дочерних (раздел 4).
- Решение: показываем данные API как есть. Не пересчитываем, не исправляем, не подсвечиваем.
- Почему: источник истины — API; подсветки ошибок нет в макете, а какое из чисел неверное, UI знать не может.
- Цена: пользователь видит таблицу, где суммы не сходятся. Расхождения перечислены в README.

### T7. Анимация раскрытия и сворачивания

- В прототипе: новые строки за ~300 мс вырастают и сдвигают нижние, текст проявляется, стрелка поворачивается.
- Решение: делаем так же в обе стороны.
  - Сначала место, потом текст. Высота строки задана на обрезающем блоке внутри каждой ячейки; CSS-анимация
    растит его с нуля за 300 мс по плавной кривой `cubic-bezier(0.4, 0, 0.2, 1)` и сдвигает строки ниже,
    разделитель проявляется вместе со строкой. Текст проявляется отдельно, за 250 мс с задержкой 100 мс,
    когда строке уже есть куда его поставить. При сворачивании текст гаснет за 120 мс, затем строка схлопывается.
  - Вариант выбран автором из четырёх, поднятых рядом: прежний (высота и прозрачность вместе, резкий старт),
    тот же мягче и длиннее, этот и этот же каскадом по строкам. Резкий старт выглядел рывком: первый кадр после
    клика приходит примерно через 40 мс, пока React Aria перерисовывает строки, и большая часть движения
    терялась; к тому же текст выезжал из-под обрезки на полпути.
  - Анимируются только строки, которые открыл пользователь, а не строки первой отрисовки.
  - React Aria размонтирует строки сразу, поэтому при сворачивании `TreeTable` держит родителя раскрытым
    в библиотеке, пока строки не уедут, и только потом сообщает ей новое состояние. Изменение, пришедшее
    в это время, применяется поверх: строку можно раскрыть снова, не дожидаясь конца анимации.
  - Стрелка поворачивается сразу, по состоянию, которое попросил пользователь.
  - При `prefers-reduced-motion` анимаций и задержек нет, строки закрываются сразу.
- Цена: своя логика поверх библиотеки. Скринридер узнаёт о сворачивании на время анимации позже.

### T8. Cloudflare Workers при требовании Node.js

- В брифе: Node.js REST API. Workers исполняет код в workerd, это не Node.js.
- Решение: API — приложение Hono, которое запускается на Node.js; тот же код развёрнут на Workers для демо.
- Цена: две точки входа и два способа запуска, которые нужно держать рабочими. Вход для Workers
  тестами не покрыт; его проверяют dry-run в CI и запрос к демо после деплоя (2.9).

### T9. Tab по строкам таблицы

- По паттерну treegrid, и так же в React Aria, таблица — одна остановка Tab, а по строкам ходят стрелками.
  На странице больше нечего фокусировать, поэтому второй Tab уходил со страницы.
- Решение: Tab и Shift+Tab переходят к следующей и предыдущей строке, после последней строки Tab выходит
  из таблицы. Вход в таблицу по Tab начинается с первой строки, по Shift+Tab — с последней. Стрелки, Enter
  и клик работают как прежде. Штатный режим `keyboardNavigationBehavior="tab"`
  не подошёл: он для элементов управления внутри ячеек и запирал фокус на кнопке-стрелке.
- Почему: проверяющие и пользователи первым делом нажимают Tab. Решение автора после просмотра.
- Цена: своя обработка клавиатуры и отступление от паттерна treegrid; на длинной таблице до элементов после
  неё нужно больше нажатий.

## 5. Риски и что проверить первым

Список рисков третьей редакции и чем они закрылись:

  средствами, своя `<table role="treegrid">` не понадобилась. Своё поверх библиотеки перечислено в 2.2.

  тестах проверяется по легенде, а оси и серии — в E2E.

- Вход для Workers не запускается в разработке: dry-run проходит, остальные проверки — в CI (2.9).

## 7. Процесс разработки

- Claude Code на Opus 5.5 ведёт реализацию по этапам из раздела 8.
- Figma MCP — точные значения из копии макета (размеры, цвета, шрифты). Вызовы только по списку из 8.1.
- Playwright MCP — проверка в браузере; он же открывает оригинал макета и прототип. Его файлы пишутся
  в `.playwright-mcp/`, папка в `.gitignore`.
- Остановки на просмотр после этапов 2 и 6 автор снял: реализация шла без остановок до рабочего решения,
  отчёты этапов собраны в итоговом отчёте, а факты из них внесены в эту редакцию.
- Каждое изменение — отдельный коммит; на каждом коммите проходят lint, проверка типов и тесты.
- Этот ADR — источник решений. Если при реализации решение не подходит, исполнитель не меняет его молча:
  описывает расхождение в отчёте, а в ADR правка вносится после согласования.
- ADR ведётся на двух языках. Исходник — этот файл, английский [ADR.md](ADR.md) — его перевод. Содержание
  у них одно: правка вносится в этот файл и одним коммитом переносится в перевод, а если они расходятся,
  верен этот файл.

Правила, по которым работали:

- Ответ обрезан или слишком велик — вызов на том же узле не повторяем, берём узел меньше.
- Всё, что видно глазами (общий вид, hover, анимация прототипа), смотрим в браузере через Playwright
  на оригинале макета. MCP на это не тратим; эталонный снимок Mockup 2 тоже снят в браузере.
- Значения сразу записываются в `client/src/styles/tokens.scss`, фотографии — в `client/src/assets/avatars/`.
  Повторно за тем же значением в Figma не ходим.
- Вызовы сверх восьми — только с согласия автора.

**Проба.** Временная страница с payload из задания и `Table` из React Aria; её код стал `TreeTable`.
